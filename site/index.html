STEP 1 · THE QUESTION

Can better tools let a cheaper model do the job?

When we want an agent to be more reliable, we usually reach for a stronger model. It often works — but it's the expensive fix, and the bill grows with every run. So we asked the opposite question: if we give a cheap model better tools, can it be accurate and cost-effective at the same time?

Scout is the research agent we built to find out. It answers hiring questions from a frozen archive of product-manager job postings. We gave the same questions to four model-and-tool combinations, graded every answer against a verified key, and compared accuracy, cost and time.

STEP 2 · WHY THE WORK IS HARD

Counting records is not answering the question

“Is hiring for agent-building skills increasing?” sounds like arithmetic. Each trap below is a real case in this archive where the arithmetic is right and the answer is still wrong.

TRAP 1

Duplicates inflate counts

One opening can be captured several times, across boards and locations.

records → openings
TRAP 2

A collection gap looks like a decline

Missing data and absent hiring make the same shape. A source can report success and return nothing.

→
TRAP 3

Mentions are not requirements

A posting can be entirely about agents and still ask nothing of the candidate. Headings decide.

All three traps describe captured postings — what the pipeline collected, never the market itself. Trap 1 is bookkeeping a computer should do. Traps 2 and 3 need judgement, but only if the evidence is in front of you.
